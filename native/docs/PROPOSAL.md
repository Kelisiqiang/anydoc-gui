# AnyDoc 原生版 · 界面设计提案

> 目标：把 AnyDoc 从「本地服务 + 浏览器」改造成**真正的 Windows 原生窗口**，
> 让用户在软件界面里直接看到转换进度，不再需要切到网页。

---

## 一、为什么要改

现状是双击 exe 后弹出一个浏览器标签页。功能没问题，但有三个硬伤：

| 问题 | 影响 |
|------|------|
| 进度显示在浏览器里 | 用户得盯着浏览器标签，不知道程序在干什么 |
| 每次启动占用一个标签页 | 干扰用户正常浏览工作 |
| 像个「网页壳」 | 不像正经软件，降低信任感和专业感 |

原生窗口能同时解决这三点：**单窗口、进度可见、无浏览器依赖**。

## 二、技术路线（已验证可行）

### 2.1 三条路子的取舍

| 方案 | 可行性 | 视觉 | 体积 | 依赖 |
|------|--------|------|------|------|
| Tauri 2.0 | ❌ **此环境不可行** | ★★★★★ | ~20MB | WebView2 Runtime |
| WebView2 自建宿主 | ⚠️ 可行但需分发 DLL | ★★★★★ | ~15MB | WebView2 Runtime（Win10 常需另装） |
| **原生 Win32（windows-rs）** | ✅ **已验证通过** | ★★★★ | **~7MB** | 无（系统自带 DLL） |

**Tauri 为什么不行**：Tauri 的 Windows 构建官方要求在 Windows 上执行（需要 MSVC 工具链 + WebView2 SDK），无法从 Linux 交叉编译。已在本地实测 `cargo tauri` 在 Linux 上直接报缺 webkit2gtk。

**最终选型：原生 Win32 + windows-rs 0.58**

已实测通过的 API 组合：

```
✅ 窗口创建 / 消息循环       RegisterClassW + CreateWindowExW
✅ 文件拖放                 DragAcceptFiles + WM_DROPFILES
✅ 自绘任务列表             ListBox + LBS_OWNERDRAWFIXED + WM_DRAWITEM
✅ 真实文件图标             SHGetFileInfo（系统图标，非 emoji）
✅ 进度条                  msctls_progress32 + PBS_SMOOTH
✅ 现代文件夹选择器         IFileDialog（COM）
✅ 深色模式                DwmSetWindowAttribute
✅ Win11 圆角/亚克力        DwmSetWindowAttribute
```

探针程序实测编译产物：**249KB**（不含 anydoc 内核），加上内核约 **7MB**。

### 2.2 关键设计决策

**① 内核用 Rust crate，不用 WASM**

Web 版用 `@firecrawl/anydoc-wasm`（6.7MB）是因为当时只能在浏览器跑。原生版是真正的本地进程，
直接用 `anydoc` crate（crates.io，MIT），**省掉 6.7MB 的 WASM**，也省掉 WebView2 依赖。

**② 转换跑在后台线程池**

`std::thread` + 通道（channel）回传结果，UI 线程只收消息刷新控件。
Windows 原生控件**不是线程安全的**，所以所有 UI 更新必须回到主线程。

**③ 列表用自绘而非 SysListView32**

`SysListView32` 样式难控、想要现代圆角/徽章几乎做不到。
改用 `ListBox + LBS_OWNERDRAWFIXED`，在 `WM_DRAWITEM` 里完全自绘 —— 想画什么画什么，
还能显示真实文件图标和圆角状态徽章。

### 3.2 设计要点

**① 投放区压缩成一条**

上一版拖拽区占了 96px，浪费纵向空间。新版压到 62px，把空间让给列表——
列表才是用户真正盯的地方。

**② 每个任务一个状态徽章**

用圆角药丸（pill）而不是纯文字，因为「颜色 + 形状 + 文字」三重编码在小尺寸下辨识度最高：

| 状态 | 颜色 | 形状 | 文字 |
|------|------|------|------|
| 等待 | 灰 `#98A2B3` / 底 `#F2F4F7` | 实心小点 | `等待` |
| 转换中 | 靛蓝 `#4F46E5` / 底 `#EEF2FF` | 脉冲小点 | `转换中` |
| 成功 | 绿 `#12B76A` / 底 `#E7F8F0` | ✓ | `✓ 12ms` |
| 失败 | 红 `#F04438` / 底 `#FEF0EF` | ✗ | `✗ 需 OCR` |

失败时**直接显示原因**（如「需 OCR」），不给「转换失败」这种无信息量的话。

**③ 成功徽章带耗时**

`✓ 12ms` 一行同时给了「成了」和「多快」两个信息，零额外空间成本。

**④ 双层进度**

- **行内**：每个任务自己的状态（等待/转换中/完成）
- **底部**：总进度条 + `3/6（2 个进行中）`

「进行中数量」这个信息很关键——它让用户知道程序还在动，没卡死。

**⑤ 真实系统图标**

用 `SHGetFileInfo` 取 Windows 自带的文件类型图标（Word 蓝标、Excel 绿标），
比 emoji 更专业，也不需要打包字体。

**⑥ 跟随系统深色模式**

用 `DwmSetWindowAttribute` + `DWMWA_USE_IMMERSIVE_DARK_MODE`，
并在 `WM_SETTINGCHANGE` 里响应切换。

### 3.3 配色

| 用途 | 色值 |
|------|------|
| 窗口底（Win11 Mica 近似） | `#F3F3F6` |
| 卡片 | `#FFFFFF` |
| 分割线 | `#E4E7EC` |
| 主色 | `#4F46E5` |
| 成功 / 失败 | `#12B76A` / `#F04438` |

## 四、交互流程

```
        ┌──────────────┐
        │  启动 exe     │
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │  窗口显示     │  ← 立刻可见，不开浏览器
        │  空状态提示   │
        └──────┬───────┘
               ↓
    ┌──────────┴──────────┐
    ↓                     ↓
┌────────┐          ┌──────────┐
│拖入文件 │          │选文件/目录│
└───┬────┘          └────┬─────┘
    └──────────┬──────────┘
               ↓
        ┌──────────────┐
        │  列表出现条目 │  ← 立即显示「等待」
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │  点「转换」   │  ← 或拖入后自动开始
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │ 后台线程池转换 │  ← UI 不卡，行内状态实时变
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │ 写盘到输出目录 │  ← 保留子目录结构
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │  底部汇总     │  「3 成功 · 1 失败 · 0.4s」
        └──────────────┘
```

**关键交互决策：拖入后是否自动开始转换？**

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. 自动开始 | 少一次点击 | 用户可能只想看看能不能转，误操作产生一堆 .md |
| **B. 手动点「转换」（推荐）** | 用户确认输出目录后再动手 | 多一次点击 |

**推荐 B**，并且流程是：先拖文件 → 选输出目录 → 点「转换」。这样输出目录一定在用户确认过之后才生效。

## 五、交付形态（只保留免安装版）

按你的要求，**去掉 NSIS 安装包**，只留一个 zip：

```
AnyDoc-v0.3.0-win-x64-portable.zip  (~7MB)
└── AnyDoc/
    ├── AnyDoc.exe          ← 原生窗口，双击即用
    ├── anydoc.exe          ← 命令行版（可选，附赠）
    └── README.md
```

**特点**：
- 解压即用，**不写注册表、不装到 Program Files、不留卸载项**
- 可以放 U 盘里带走
- 绿色软件该有的样子

## 六、工作量与风险

| 项目 | 评估 |
|------|------|
| Win32 窗口框架 | ✅ 已验证（探针程序编译通过） |
| 拖放 + 文件对话框 | ✅ API 已确认可用 |
| 自绘列表（徽章/图标/动画） | ⚠️ 需写 `WM_DRAWITEM`，约 300 行 |
| 后台线程池 + 消息回传 | ⚠️ 约 200 行，注意 UI 线程亲和性 |
| Win11 圆角/深色模式 | ⚠️ 约 50 行，Win10 自动降级 |
| 真实图标获取 | ⚠️ 约 80 行（SHGetFileInfo + ImageList） |
| **合计** | **约 1200-1500 行 Rust** |

**风险与对策**：

| 风险 | 等级 | 对策 |
|------|------|------|
| 自绘列表细节（滚动、选中、键盘导航） | 中 | 用 ListBox 托管滚动和焦点，只自绘行内容 |
| Win10 与 Win11 视觉差异 | 低 | 圆角/亚克力用 DWM，Win10 自动忽略 |
| 线程安全 | 中 | 严格「UI 只在主线程改」；转换结果用 channel 送回 |
| 深色模式配色 | 低 | 自绘时按 `WM_SETTINGCHANGE` 重绘 |

**已知的取舍**：纯 Win32 绘制的视觉效果不如 WebView2 精细（无法用 CSS 阴影/渐变/圆角任意组合），
但换来的是**零运行时依赖 + 7MB 体积 + 启动即现**。对「发给别人用」这个场景，体积和无依赖比像素级精美更重要。
